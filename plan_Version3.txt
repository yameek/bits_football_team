1) Overview
1.1 Purpose
Support a football team’s treasurer to:
- Book fields and plan sessions (practice/match) and track upcoming sessions
- Record attendance and automatically allocate session costs ONLY to attendees
- Collect monthly contributions and on-field payments (including guests/new members)
- Track team and individual balances; share transparent financials with management

1.2 Goals
- Accurate per-session fee allocation with rounding policy
- Clear member and team balances
- Fast on-field workflows (attendance, payments)
- Shareable reports/dashboards; export support
- Privacy- and compliance-ready

1.3 Scope (v1)
- Session, field, member management
- Attendance with status (present/late/absent)
- Cost breakdown and automatic per-head deduction
- Contributions, on-field collections, transactions log with categories
- Team and individual balances, reports/exports
- RBAC (recommended) with option to run single-user mode (no auth)

Out of scope (v1)
- Online payment gateway (can be added later)
- Push/email/SMS notifications (optional later)
- Multi-currency and complex accounting
- Real-time sync/offline-first (future)
- Multi-tenant orgs (future)


2) Stakeholders & Roles
- Treasurer: Finance ops, sessions, attendance, approvals, reports
- Manager/Coach: Schedule sessions, mark attendance, read-only finance summaries
- Members: View their balance/transactions; optionally pay contributions
- Management/Viewer: Read-only dashboards/reports
- Admin: User/role management, system configuration

RBAC can be disabled for single-user deployments. When disabled, all actions are allowed to the local user.


3) Business Rules
BR-01 Per-head fee = round(total_session_cost / number_present, 2)
BR-02 Rounding difference handled via:
  - Adjustment transaction at team level; or
  - Distribute ±0.01 across first N attendees to exactly match total
BR-03 Only attendees are charged; absent members are not charged under any circumstance
BR-04 “Late” attendance status counts as present by default; configurable per session or globally
BR-05 Contributions increase member balance; not tied to a specific session
BR-06 Insufficient balance: allow partial deduction; remaining due covered by on-field payment or future contribution
BR-07 On-field collection is recorded immediately; it offsets the session due first
BR-08 Transactions are immutable in soft-delete mode; corrections use refunds/adjustments; 
      In “hard delete” compliance mode, member deletion cascades deletes to related records
BR-09 Team balance = sum of member balances (optionally show separate cash ledger if used)
BR-10 Guest attendees: allow ad-hoc attendee capture; fees collected on-field; can later be converted to a member
BR-11 Attendance uniqueness: (member_id, session_id) must be unique
BR-12 Charges auto-apply only after session is finalized/locked

5.3 SQL DDL (PostgreSQL)
CREATE TABLE members (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    contact_number VARCHAR(20),
    balance DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    status VARCHAR(20) NOT NULL DEFAULT 'active',
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE fields (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    address TEXT,
    google_map_link VARCHAR(255),
    latitude NUMERIC(10,8),
    longitude NUMERIC(11,8),
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE categories (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    color VARCHAR(7),
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE sessions (
    id SERIAL PRIMARY KEY,
    field_id INT REFERENCES fields(id) ON DELETE SET NULL,
    name VARCHAR(255),
    scheduled_start TIMESTAMP NOT NULL,
    scheduled_end TIMESTAMP,
    session_type VARCHAR(20) NOT NULL CHECK (session_type IN ('practice','match')),
    field_cost DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    transport_cost DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    drinks_cost DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    emergency_fund DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    other_costs DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    notes TEXT,
    status VARCHAR(20) NOT NULL DEFAULT 'planned',
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE attendance (
    id SERIAL PRIMARY KEY,
    member_id INT NOT NULL REFERENCES members(id) ON DELETE CASCADE,
    session_id INT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    status VARCHAR(10) NOT NULL CHECK (status IN ('present','late','absent')),
    charged_amount DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    paid_amount DECIMAL(12,2) NOT NULL DEFAULT 0.00,
    payment_method VARCHAR(10) CHECK (payment_method IN ('balance','cash','mixed')),
    paid_flag BOOLEAN NOT NULL DEFAULT FALSE,
    notes TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (member_id, session_id)
);

CREATE TABLE transactions (
    id SERIAL PRIMARY KEY,
    member_id INT REFERENCES members(id) ON DELETE CASCADE,
    session_id INT REFERENCES sessions(id) ON DELETE SET NULL,
    category_id INT REFERENCES categories(id) ON DELETE SET NULL,
    transaction_type VARCHAR(30) NOT NULL CHECK (transaction_type IN ('contribution','session_fee','onfield_payment','refund','adjustment')),
    amount DECIMAL(12,2) NOT NULL,
    currency VARCHAR(10) NOT NULL DEFAULT 'USD',
    method VARCHAR(10) CHECK (method IN ('cash','bank','mobile')),
    timestamp TIMESTAMP NOT NULL DEFAULT NOW(),
    reference VARCHAR(100),
    notes TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

-- Optional auth/audit (enable if RBAC is on)
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(150) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('admin','treasurer','manager','member','viewer')),
    member_id INT REFERENCES members(id) ON DELETE SET NULL,
    last_login_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE audit_logs (
    id SERIAL PRIMARY KEY,
    user_id INT REFERENCES users(id) ON DELETE SET NULL,
    action VARCHAR(50) NOT NULL,
    entity_type VARCHAR(50) NOT NULL,
    entity_id INT,
    payload_snapshot JSONB,
    ip INET,
    ua TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);

6) Core Algorithms
6.1 Total Session Cost
total_cost = field_cost + transport_cost + drinks_cost + emergency_fund + other_costs

6.2 Headcount
present_count = count(attendance where status in ('present','late') respecting config for late)

6.3 Per-Head Fee
raw_fee = total_cost / present_count
per_head_fee = round(raw_fee, 2)
rounding_diff = total_cost - (per_head_fee * present_count)
Handle rounding_diff per BR-02

6.4 Auto-Deduction
For each attendee counted as present:
- if balance >= per_head_fee:
    - create transaction(session_fee, -per_head_fee, method=balance, category optional e.g., "match fee")
    - member.balance -= per_head_fee
    - attendance.charged_amount = per_head_fee
    - attendance.paid_amount += per_head_fee
    - attendance.paid_flag = true; payment_method='balance'
- else:
    - deduct partial if any balance > 0; set due = per_head_fee - partial
    - record session_fee for partial; zero out balance
    - attendance.charged_amount = per_head_fee
    - attendance.paid_amount += partial
    - paid_flag=false; payment_method='mixed' or null

6.5 On-Field Collection
- transaction(onfield_payment, +amount, method=cash/mobile, session_id set)
- Apply to unpaid attendance for that session first
- When paid_amount >= charged_amount => paid_flag = true

6.6 Contributions
- transaction(contribution, +amount, category optional like "monthly contribution")
- member.balance += amount

6.7 Deletion Mode
- Soft-delete (default for audit): deactivate member; prevent new activity; retain data
- Hard-delete (compliance mode): cascade delete attendance, transactions; remove PII; log audit anonymized “erasure” event

11) Acceptance Criteria (selected)
AC-01 Session finalize charges only attendees (present/late if configured) and leaves absentees untouched
AC-02 Member with insufficient balance: partial deduction recorded; unpaid due cleared by on-field payment; paid_flag toggles when fully covered
AC-03 Rounding: totals exactly match cost using chosen rounding policy
AC-04 Contribution increases balance and logs as contribution transaction; category optional
AC-05 Hard delete mode: deleting a member cascades attendance/transactions; confirmation dialog shown
AC-06 Dashboard shows team balance = sum(member balances), counts of positive/negative balances, upcoming sessions
AC-07 Categories: user can create/view/delete; transactions filterable by category


12) Flow Diagrams (Mermaid)

12.1 Session Lifecycle & Payment
flowchart TD
    A[Create Session] --> B[Enter Costs<br/>(Field, Transport, Drinks, Emergency, Other)]
    B --> C[Schedule Date/Time & Field]
    C --> D[Mark Attendance: Present/Late/Absent]
    D --> E{Finalize Session?}
    E -- No --> D
    E -- Yes --> F[Compute Total & Per-Head Fee]
    F --> G{Any billable attendees?}
    G -- No --> H[Abort Fees<br/>Notify & Log]
    G -- Yes --> I[Auto-Deduct per attendee]
    I --> J{Sufficient Balance?}
    J -- Yes --> K[Create session_fee Tx<br/>Update Balance<br/>Mark Paid]
    J -- No --> L[Partial Deduction<br/>Record Due]
    L --> M[On-Field Collection or Contribution]
    M --> N[Reconcile Dues<br/>Mark Paid when covered]
    K --> O[Handle Rounding Adjustment]
    N --> O
    O --> P[Generate Session Report]
    P --> Q[Session Complete]

12.2 Contribution Flow
flowchart LR
    C1[Receive Contribution] --> C2[Create contribution Tx]
    C2 --> C3[Increase Member Balance]
    C3 --> C4[Reflect in Team Balance & Statement]

12.3 Category Management
flowchart LR
    X1[Create Category<br/>(e.g., Food Fee)] --> X2[Assign to Transactions]
    X2 --> X3[Filter Reports by Category]

12.4 Deletion (Compliance vs Audit)
flowchart TD
    D1[Delete Member Action] --> D2{Mode?}

    D2 -- Hard --> D4[Cascade Delete<br/>Transactions & Attendance]
